# Technical Ownership Card — M0a.2 VMs órfãs

- **Mudou:** a descoberta mantém todas as VMs válidas do MSB e deriva `orphaned` comparando o projeto do nome da VM com os diretórios reais. O frontend sinaliza a ausência; `projects` não recebe entradas sintéticas.
- **Decisão:** inventário MSB e inventário de diretórios são fatos independentes. `src/discovery.ts` preserva a VM, ordena o snapshot e marca a relação ausente. `src/model.ts` torna `orphaned` parte explícita do contrato API/SQLite.
- **Fluxo:** argv read-only do MSB → parser estrito → `listProjects` somente leitura → marcação/ordenação em discovery → validação de coerência e persistência SQLite → API → rótulo visual. `src/host-check.ts` publica somente as contagens `projects`, `vms` e `orphaned_vms`.
- **Invariantes:** nenhuma VM com nome/status/schema inválido entra; nenhuma pasta é criada; a lista de projetos contém apenas diretórios reais; `SnapshotStore.replace` recusa um marcador órfão incoerente e `read` revalida as linhas; falha antes/durante discovery não substitui o snapshot anterior.
- **Migração:** `src/store.ts` reconhece apenas o schema próprio v1 exato e migra transacionalmente para v2. Bancos estrangeiros continuam recusados. A nova tabela remove a FK que obrigava projeto fictício e grava `orphaned` com `CHECK` booleano.
- **Diagnóstico:** se `msb list --format json` e `/api/vms` divergirem, compare `counts.vms`/`counts.orphaned_vms`; depois inspecione parser, lista real de diretórios e `orphaned`. Não apague banco nem crie diretório para mascarar a divergência.
- **Evidência/exercício:** revisão independente sem achado bloqueante; typecheck e 45 testes direcionados passaram nessa revisão. A suíte final está registrada em `docs/m0a2-verification.json`. Este card foi escrito antes da verificação do host. Em 2026-10-25 o operador atestou a validação no Arch real; [m0a2.md](m0a2.md) separa esse aceite manual das evidências automatizadas locais, sem inventar a saída ausente do host-check.
